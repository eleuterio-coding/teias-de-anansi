# Teias de Anansi 2.0 — Etapa 1, item 1.06: GitHub Pages (preparação sem publicação)

**Data:** 19/11/2026

## Objetivo e limites

Preparar a aplicação Vite para o futuro endereço
`https://eleuterio-coding.github.io/teias-de-anansi/`, conferindo o caminho-base, o carregamento das rotas internas, a construção estática e a geração de artefato de teste. O item **não** autoriza publicação, mudança na fonte de Pages, merge, configuração de credenciais, Firebase, API ou a preparação de 1.07.

### Caminho base

`vite.config.ts` contém:

```ts
base: '/teias-de-anansi/',
```

Vite emite, no `dist/index.html`, URLs para arquivos de JS/CSS começando por `/teias-de-anansi/`. Não usar `base: '/'`, pois isso apontaria os recursos para a raiz de `eleuterio-coding.github.io`, fora do repositório do projeto.

### Rotas internas e recarregamento

O `HashRouter` aprovado no item 1.05 segue URLs como:

- `https://eleuterio-coding.github.io/teias-de-anansi/#/` — início.
- `https://eleuterio-coding.github.io/teias-de-anansi/#/biblioteca` — módulo provisório.
- `https://eleuterio-coding.github.io/teias-de-anansi/#/personagens` — módulo provisório.

A parte que o servidor recebe é sempre `/teias-de-anansi/`: o fragmento `#/...` é tratado pelo navegador. Um recarregamento não exige que o GitHub Pages encontre um arquivo físico na subrota. **URLs sem hash, como `/teias-de-anansi/biblioteca`, não estão preparadas** e podem gerar 404 do servidor. Não foi criado `404.html` de redirecionamento, pois ele é desnecessário neste modo.

Os testes `tests/github-pages-routing.test.tsx` simulam navegação, desmontagem/remontagem da aplicação no mesmo endereço e 404 em `jsdom`. Eles **não equivalem a teste em hospedagem pública**.

### Build e artefato sem deploy

O workflow `.github/workflows/verificar-tecnologias.yml`:

1. Executa exclusivamente na branch `feature/etapa-1-fundacao-8-etapas` (ou disparo manual).
2. Instala dependências com `npm ci` a partir do lockfile versionado.
3. Roda TypeScript, ESLint, Vitest, Prettier e `npm run build`.
4. Roda `npm run pages:check`, conferindo o `index.html` gerado, as URLs de JS/CSS e a existência dos arquivos em `dist/`.
5. Arquiva `dist/` via `actions/upload-artifact@v4` como **artefato de CI** com retenção de 7 dias. Esse artefato **não** é publicação GitHub Pages nem um site hospedado.

O workflow mantém `permissions: contents: read`; não chama `actions/deploy-pages`, `actions/upload-pages-artifact`, não escreve em `gh-pages` e não acessa ambientes ou credenciais de produção.

### Comandos para desenvolvimento e conferência local

Com Node.js >=20.19 e npm:

```bash
npm ci
npm run typecheck
npm run lint
npm run test:run
npm run format:check
npm run build
npm run pages:check
npm run preview
```

Com `npm run preview`, abrir a URL informada pelo Vite **com o caminho `/teias-de-anansi/`**; por padrão, poderá ser `http://localhost:4173/teias-de-anansi/#/`. O comando de preview não publica o site.
