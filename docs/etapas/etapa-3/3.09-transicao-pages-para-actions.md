## Operação manual obrigatória no GitHub (quando o dispatcher estiver pronto)

1. Abra **[Configurações Pages do mesmo repositório](https://github.com/eleuterio-coding/teias-de-anansi/settings/pages)**.
2. Em **Build and deployment → Source**, altere **Deploy from a branch** para **GitHub Actions**.
3. **Não** clique em *Configure* para criar um template, **não** crie site/repositório/branch `gh-pages`, **não** mude domínio personalizado ou configurações HTTPS.
4. Confirme que a URL exibida ainda é `https://eleuterio-coding.github.io/teias-de-anansi/`.
5. **Interrompa aqui**, sem executar workflow. Depois da alteração, reabrir a conferência GET. Alterar Source não publica automaticamente a aplicação. A mudança pode alterar o caminho de publicação do site até o primeiro deploy; portanto deve ser coordenada com a ativação do dispatcher e não feita antecipadamente fora da janela de corte.

**Em caso de interrupção antes do primeiro deploy**: em Settings → Pages → Build and deployment → Source, voltar para **Deploy from a branch**, escolher `main` e `/` (root), salvar e confirmar o endereço HTTPS. Não tocar nas Rules antigas por essa operação. Restaurar Source é reversão de configuração, não garantia de tempo de propagação.

Referências oficiais: https://docs.github.com/en/pages/getting-started-with-github-pages/configuring-a-publishing-source-for-your-github-pages-site e https://docs.github.com/en/actions/how-tos/manage-workflow-runs/manually-run-a-workflow.

## Ordem técnica segura — sem publicação prematura

1. **Manter branch, main e site intactos** enquanto as proteções do ambiente `github-pages` e a permissão real de `pages:write`/`id-token:write` não forem demonstradas. O GET de ambiente pode descrever regras de proteção, mas não prova que o token fará o deploy. Não assumir sucesso.
2. Validar fluxo manual na CI por YAML e contratos offline, congelar SHA da branch homologada. Não usar o SHA antigo após qualquer alteração posterior.
3. **Somente na janela coordenada**, copiar **exclusivamente** `.github/workflows/publicar-etapa-3-manual.yml` à `main` mediante commit mínimo e verificação do SHA antigo. Não mesclar o PR #285. Esse commit pode provocar build do Pages enquanto Source ainda está em branch, motivo para evitar alteração antecipada.
4. Trocar Source em Settings → Pages para GitHub Actions conforme acima. Confirmar por GET `build_type=workflow` e URL exata; qualquer divergência bloqueia A+B.
5. Fazer execução manual de `workflow_dispatch` apenas após todas as condições: SHA integral do candidato, `PUBLICAR_A_E_B` e `LEGADO_VALIDADO` **somente após avaliação funcional apropriada**. O workflow faz testes, audita metadados reais, compara release, gera **novo** backup criptografado, aplica Rules A e implanta build via `upload-pages-artifact` + `deploy-pages` B.
6. Conferir via GET a release das Rules, HTML/JS em HTTPS, resposta das permissões e logins dos titulares. A conclusão exige aceite das cinco contas.
