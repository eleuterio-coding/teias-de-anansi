# Homologação online em segundo repositório GitHub Pages

**Aprovado pelo responsável:** usar GitHub Pages + Firebase, com página de testes publicamente acessível, **somente se o conteúdo privado estiver protegido pelas Security Rules corrigidas**. **Não** foi autorizada a publicação dessas Rules.

## Repositório independente

Nome reservado: `eleuterio-coding/teias-de-anansi-homologacao`.

Endereço **futuro (ainda não publicado)**: `https://eleuterio-coding.github.io/teias-de-anansi-homologacao/`.

A API do GitHub conectada neste chat não oferece criação de repositórios. Cabe ao proprietário abrir `https://github.com/new` e criar um repositório público com o nome `teias-de-anansi-homologacao`, marcando **Add a README file** para inicializar a branch `main`. Repositórios públicos podem hospedar GitHub Pages. Não copiar o código nem mergear `main` do Hub oficial no repositório novo.

Com o repositório existente e acessível à integração GitHub, a implantação segura deverá seguir:

1. Criar nele a única workflow `.github/workflows/pages.yml`, a partir do modelo `docs/etapas/etapa-3/github-pages-homologacao.yml` deste repositório.
2. Em **Settings → Pages**, escolher **GitHub Actions** como fonte de publicação.
3. Executar manualmente o workflow, que cria e publica **somente a página de preparação**, sem SDK Firebase nem login; verificar o link online.
4. Após revisão e **aprovação independente** da publicação das Security Rules com testes de compatibilidade, substituir o passo da página de preparação por um checkout da branch `feature/etapa-3-usuarios-acesso-20261120`, instalar dependências e executar `npm run build:github-homologacao`, publicando apenas `dist`.
5. Executar com as cinco contas existentes somente depois de verificar acesso negado a documentos de outros titulares na perspectiva de sessão autenticada, sem compartilhar senhas ou dados.

## Bloqueio de segurança

A aplicação final em `dist` contém configuração pública do Firebase e **nunca** pode conter uma service account, token administrativo ou senha. Os dados de outros usuários precisam ser protegidos **no servidor**, por Security Rules, mesmo que o HTML e JS sejam públicos. As Rules atuais permanecem históricas, com 12 permissões excessivas reproduzidas no emulador: a aplicação com login permanece **bloqueada para publicação**.

**Não há URL de testes funcionando neste momento.** O primeiro passo externo é criar o segundo repositório; a etapa segura publicável inicialmente é apenas uma página informativa. Nenhum arquivo do repositório original deve ser publicado no site oficial.
