# Etapa 3.09 — Corte real A+B e recuperação de GitHub Pages (23/11/2026)

**Estado:** implantação técnica concluída, **homologação dos cinco titulares PENDENTE**. Site público restaurado no mesmo endereço; Rules restritivas A publicadas; nenhuma conta, documento ou mídia real foi alterado.

## Por que surgiu o 404

A `main` do repositório tinha somente `.github/` e `README.md`, **sem `index.html`**. Após a promoção mínima de dois workflows do [PR #286](https://github.com/eleuterio-coding/teias-de-anansi/pull/286), o GitHub Pages ainda utilizava `build_type=legacy`, com `main`/`/` como origem. Uma reconstrução da branch sem arquivo inicial originou o erro 404 mostrado no navegador.

Uma tentativa de orquestrar automaticamente o fluxo originalmente planejado A+B falhou **antes de qualquer escrita** pelo gate `build_type=legacy`: [#45218921374](https://github.com/eleuterio-coding/teias-de-anansi/actions/runs/45218921374). Não se alterou Settings → Pages.

## B — Recuperação do site na origem legacy existente

Por não haver ferramenta com administração de Pages para alterar Source, foi usada a origem **já configurada** (`legacy`, `main`/`/`), sem criar novo site ou exigir alteração manual:

1. A versão Vite da feature foi compilada com a base `/teias-de-anansi/`, após `npm run check`, testes e inspeção do artefato. A tentativa inicial abortou **sem escrever** ao detectar que o build também continha um `README.md`. Esse arquivo foi excluído da publicação para preservar o README do repositório.
2. Na [execução #45219917119](https://github.com/eleuterio-coding/teias-de-anansi/actions/runs/45219917119), o GitHub Actions adicionou **somente** os arquivos estáticos compilados à `main`: `index.html`, `.nojekyll` e 20 arquivos em `assets/`; não alterou `.github/` nem `README.md`.
3. O novo HEAD de `main` é **`b8479db3b3be882a004911d41ba1a30f27a456ee`**. Requisição explícita `POST /pages/builds` devolveu **HTTP 201**.
4. A [verificação #45220269850](https://github.com/eleuterio-coding/teias-de-anansi/actions/runs/45220269850) terminou **SUCCESS**, com `PAGES_SMOKE_VERIFIED`: GET do HTML e do JavaScript correspondem **exatamente ao build**; Pages GET retornou `build_type=legacy`, `status=built`, `error=null`, URL original.
5. O único endereço permanece **https://eleuterio-coding.github.io/teias-de-anansi/**.

**Ressalva:** foi publicado o marco de autenticação e controle de acesso da **nova** aplicação, não uma reconstrução de todos os módulos RPG antigos. As rotas de mídia, aventuras e campanhas ainda são provisórias como consta na matriz de escopo.

## O que ainda não está homologado

- Cinco titulares reais devem validar **login, papel, vínculos, refresh/reabertura, navegação autorizada/negada e logout** diretamente no site; não coletar senhas, tokens ou identificadores sensíveis.
- A inspeção administrativa GET e os testes com identidades fictícias **não** substituem autorização real por token das cinco contas.
- Os módulos completos de RPG/mídia continuam fora do escopo concluído. Não assinalar como homologado um recurso de interface ainda provisório.
- A compatibilidade entre dispositivos desktop/mobile por uso real requer validação em navegador.

**Conclusão:** recuperação do 404 e implantação técnica de A+B **comprovadas**; Etapa 3.09 **ainda não formalmente encerrada** até o aceite funcional de cinco contas reais. Não é necessária mudança manual de Settings → Pages para que o site atual funcione.
