## Achado crítico confirmado por documentação oficial

O fluxo anterior executava push na main com o GITHUB_TOKEN esperando que o GitHub Pages legacy republicasse. Documentação oficial: commits enviados por workflow usando GITHUB_TOKEN **não disparam build do GitHub Pages** quando a origem é uma branch. Referência: https://docs.github.com/en/pages/getting-started-with-github-pages/configuring-a-publishing-source-for-your-github-pages-site

Ação: remover worktree/push; usar actions/upload-pages-artifact@v3 e actions/deploy-pages@v4, com permissões pages:write e id-token:write. O site continua no mesmo URL, sem segundo repositório. O workflow faz GET /repos/.../pages e exige build_type=workflow antes de consultar/alterar Rules; com configuração legacy, **falha antes de A**. Nenhuma configuração foi alterada remotamente.
