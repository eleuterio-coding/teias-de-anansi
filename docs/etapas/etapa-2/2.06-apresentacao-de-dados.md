# 2.06 — Componentes de apresentação de dados

**Data:** 20/11/2026  
**Situação:** implementado na branch de desenvolvimento, aguardando revisão e aprovação do Mestre.  
**Autorização:** 2.05 aprovado expressamente em 20/11/2026, com ciência de testes automatizados e inspeções visuais ainda pendentes.

## Objetivo

Criar uma camada visual e comportamental única para consultar e apresentar coleções de dados do Hub. Esta entrega é **agnóstica de domínio**: nenhum componente acessa Firestore/Firebase, autentica usuários, cria fichas ou publica registros.

A linguagem segue a fantasia sombria editorial aprovada: superfície escura, tipografia legível, bordas discretas, ouro envelhecido como destaque e nenhum ornamento que dificulte a leitura de dados.

## Componentes entregues

| Componente | Arquivo | Contrato |
| --- | --- | --- |
| Tabela | `DataTable.tsx` | Colunas genéricas, função de renderização por célula, cabeçalhos, ordenação externa opcional, legenda e overflow horizontal acessível |
| Lista | `DataList.tsx` | Itens genéricos, chave estável, renderização customizável, estado vazio |
| Busca | `SearchField.tsx` | Campo rotulado, valor controlado e ação real de limpeza |
| Filtro | `FilterSelect.tsx` | Opções com `value/label`, associação label e mudança controlada |
| Paginação | `Pagination.tsx` | Contagem, limites, anterior/próxima, estado desabilitado |
| Indicador | `ProgressMeter.tsx` | HTML `progress` nativo, porcentagem visível, valores limitados ao intervalo válido |
| Vazio | `EmptyState.tsx` | Título, descrição e ação opcional para ausência de registros |
| Carregando | `DataLoading.tsx` | Estado de carregamento separado do vazio, `role="status"` |
| Exploração | `DataExplorer.tsx` | Busca textual, um filtro categórico, sort estável, paginação após filtros e alternância tabela/lista opcional |

Todos os exports públicos passam por `src/components/data/index.ts`.

## Contratos e escolhas deliberadas

**Fonte dos dados:** os componentes recebem `items` e funções de projeção; **não** carregam dados sozinhos. A página/módulo responsável deve validar permissões, buscar registros permitidos e tratar falhas antes de repassá-los.

**Identidade:** `src/styles/data.css` usa exclusivamente variáveis semânticas de `src/styles/tokens.css`. `src/app/main.tsx` importa a folha uma vez, depois da base visual.

**Busca:** `DataExplorer` usa o texto devolvido por `searchText(item)`, pesquisa sem diferenciar maiúsculas/minúsculas ou acentos, e não varre arbitrariamente campos privados. A filtragem e a ordenação operam apenas em memória.

**Filtro:** um filtro categórico opcional, controlado pela função `getValue(item)`, com opção para todas as categorias. Filtros múltiplos e pesquisas remotas exigem contrato próprio antes de implementação.

**Ordenação:** colunas só são ordenáveis quando contêm função `sortValue`. Colunas de texto usam `Intl.Collator('pt-BR', { numeric: true, sensitivity: 'base' })`; números usam comparação numérica. Em igualdade, preserva-se a ordem de entrada.

**Paginação:** após filtragem e ordenação, tamanho de página positivo, limites de página calculados por contagem real, anterior/próxima desabilitados nos extremos e contagem visível. Busca, filtro e ordenação reiniciam na primeira página.

**Estados:** o sinal `loading` tem precedência sobre os estados vazios. Uma lista sem itens apresenta "Nenhum registro disponível"; resultados filtrados sem correspondência mostram "Nenhum resultado encontrado" e podem limpar filtros.

**Alternância de visualização:** o controle "Lista" só aparece quando a página fornece `renderListItem`, evitando um botão sem efeito.

**Acessibilidade:** tabelas usam `table/caption/th scope="col"`; cabeçalhos ordenáveis contêm botões com `aria-sort`. A região de tabela com overflow recebe foco por teclado e rótulo acessível. Inputs e selects são rotulados. O progresso é nativo e expressa a porcentagem também como texto.

**Escala de dados:** a implementação é indicada para coleções pequenas e médias **já carregadas**. Não há paginação servidor, virtualização, cache, índices, persistência de filtros em URL ou busca remota neste item. Não utilizar com milhares de registros sem avaliar desempenho e proteção de dados.

## Exemplos de uso

```tsx
import {
  DataExplorer,
  ProgressMeter,
  type DataColumn,
} from '../../components/data';

type TomoPublico = {
  id: string;
  titulo: string;
  categoria: string;
  paginasLidas: number;
};

const columns: DataColumn<TomoPublico>[] = [
  {
    id: 'titulo',
    header: 'Título',
    cell: (item) => item.titulo,
    sortValue: (item) => item.titulo,
  },
  {
    id: 'progresso',
    header: 'Leitura',
    cell: (item) => (
      <ProgressMeter
        label="Progresso de leitura"
        value={item.paginasLidas}
        max={100}
      />
    ),
    sortValue: (item) => item.paginasLidas,
  },
];

<DataExplorer
  items={tomosAutorizados}
  columns={columns}
  getKey={(tomo) => tomo.id}
  label="Tomos autorizados"
  searchText={(tomo) => tomo.titulo}
  filter={{
    label: 'Categoria',
    options: [{ value: 'lore', label: 'Conhecimento' }],
    getValue: (tomo) => tomo.categoria,
  }}
  pageSize={10}
  loading={carregando}
/>
```

O exemplo é **ilustrativo**, não foi integrado a uma rota real e não representa dados de usuários. As variáveis `tomosAutorizados` e `carregando` são entradas a serem providas posteriormente pelos módulos.

## Verificações

**Criados:** 19 cenários de testes com registros inteiramente fictícios, cobrindo renderização, carregamento, estados vazios, busca sem acentos, filtros, ordenação alfabética/numericamente, paginação, lista, acessibilidade e progresso.

**Conferências estáticas realizadas:** leitura de volta de 16 arquivos da
biblioteca, estilos, integração, testes e documentação. O módulo de entrada
importa `data.css` uma única vez; os nove componentes de apresentação
estão exportados pelo `index.ts`. Não há variáveis `--ds-*` sem definição
no CSS de dados, nem cores hexadecimais locais, nem referências diretas
às APIs Firebase/Firestore nos componentes criados. Foram contados 19 testes
escritos, sem execução confirmada.

**Pendentes:** execução efetiva de `npm run check` (TypeScript, ESLint, Vitest, Prettier, fronteiras, build), resultados confirmados da CI, inspeção em navegadores e dispositivos reais, auditoria com leitor de tela e testes de escala/performance. Testes escritos não constituem aprovação técnica.

## Critérios de aceite

1. Biblioteca genérica de dados com API tipada e sem dependência de módulos.
2. Busca, filtro, ordenação, paginação e troca de visão com resultados corretos.
3. Distinção entre carregamento, coleção vazia e busca sem correspondência.
4. Estados e controles acessíveis por teclado e com rótulos apropriados.
5. Uso exclusivo da identidade e dos tokens globais.
6. Regras e testes documentados com status real de execução.
7. Nenhum merge, deploy, acesso a dados privados ou mudança Firebase.
