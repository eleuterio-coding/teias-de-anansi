# 2.05 — Componentes de interação

**Data:** 20/11/2026  
**Status:** implementado na branch isolada e aguardando testes e aceite.  
**Autorização:** o Mestre aprovou expressamente o item 2.04, mesmo ciente
das pendências de testes automatizados e inspeção visual, e pediu que 2.05
fosse iniciado sem merge nem publicação.

## Objetivo

Eliminar divergências entre módulos por meio de componentes React reutilizáveis,
estilizados com tokens de identidade da Etapa 2.02. A biblioteca contém
comportamentos reais e contratos tipados, não apenas classes CSS.

## Implementação

| Componente | Arquivo | Contrato principal |
| --- | --- | --- |
| Botão | `Button.tsx` | variantes, tamanhos, loading/disabled, type seguro |
| Link | `HubLink.tsx` | link interno React Router ou externo, variantes e segurança |
| Card | `Card.tsx` | estrutura, texto opcional, ações e versão editorial ornamentada |
| Etiqueta | `Badge.tsx` | tons semânticos e rótulos textuais |
| Aviso | `Alert.tsx` | título, mensagem, status/alert, fechamento opcional |
| Abas | `Tabs.tsx` | setas, Home/End, seleção ARIA e itens desabilitados |
| Menu de ações | `ActionMenu.tsx` | foco, setas, clique externo, Escape e disabled |
| Janela modal | `Dialog.tsx` | portal, foco, Tab, Escape, backdrop, retorno do foco |
| Confirmação | `ConfirmDialog.tsx` | confirmação explícita e estado busy |
| Painel expansível | `Accordion.tsx` | HTML nativo details/summary |

Todos os componentes são exportados por `src/components/ui/index.ts` e
descritos em `src/components/README.md`.

## Integração real

- `src/app/main.tsx` carrega `components.css` uma única vez, após os tokens
  aprovados e os estilos de layout/responsividade.
- `AppShell.tsx` utiliza `HubLink` nas ações da página.
- `HomePage.tsx` passa a usar `Card` e `HubLink` para a lista provisória.
- `PageErrorBoundary.tsx` utiliza `Button` e `HubLink`.
- `NotFoundPage.tsx` utiliza `HubLink`.
- Foram retiradas classes de ações duplicadas do CSS do shell, para que um
  único componente controle as variantes.

Os módulos de RPG continuam provisórios; nenhuma funcionalidade de criação,
salvamento, exclusão ou acesso aos dados reais foi habilitada.

## Acessibilidade e segurança de interação

- Botão tem `type="button"` padrão e marca `aria-busy` quando carregando.
- Links externos abertos em nova aba recebem `rel="noopener noreferrer"`.
- Abas têm `role="tablist"`, `tab`, `tabpanel`, `aria-selected` e
  navegação com setas, Home e End.
- Menu tem `aria-haspopup`, `aria-expanded`, Escape, setas e opções desabilitadas.
- Modal recebe `aria-modal`, título, foco inicial, ciclo de Tab, Escape e
  devolução do foco; bloqueia rolagem de fundo enquanto aberto.
- A confirmação nunca executa a ação sem clique expresso; operação de
  persistência e autorização pertencem ao módulo consumidor.
- Accordion usa ativação nativa por teclado.
- A aparência utiliza as mesmas cores do sistema e respeita
  `prefers-reduced-motion`.

## Testes e evidências

**Criados:** 15 cenários de testes específicos de botão, link, card, badge,
alerta, abas, menu, modal, confirmação e painel expansível em
`tests/components-interaction.test.tsx`.

**Conferências estáticas executadas:** leitura de volta de 11 arquivos da
biblioteca (dez componentes e index de exportação) e de 11 arquivos de integração,
estilo, testes e documentação. Foram encontradas **zero referências a tokens CSS
inexistentes** em `components.css`, **zero cores hexadecimais literais** nesse
arquivo e **zero chamadas diretas às APIs Firebase/Firestore** nos componentes.
O import global dos estilos, o reuso de links no AppShell e o uso de Cards na
página inicial provisória foram confirmados pelo código.

**Ainda não comprovado:** execução integral de `npm run check`,
TypeScript, lint, Prettier, Vitest e build, nem homologação visual em
Chrome/Firefox/Safari, teclado real, leitor de tela e zoom. Não confundir
arquivos de testes com testes executados. Atualizar a documentação com links de
execuções aprovadas quando existirem.

## Critérios de aprovação

1. Uma biblioteca única e tipada contém todos os dez grupos de componentes.
2. Cada controle executa a ação prevista, com estado disabled e foco coerentes.
3. Identidade consistente com paleta e tokens 2.02.
4. Componentes demonstram comportamento independente de módulos e Firebase.
5. Reuso comprovado no AppShell e nas páginas provisórias.
6. Testes e limitações documentados, sem alegar validação inexistente.
7. Branch de trabalho isolada; sem merge, deploy ou alterações remotas de dados.
