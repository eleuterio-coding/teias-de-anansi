**Data:** 20/11/2026

## Objetivo

Padronizar mensagens de sistema e feedback para operações assíncronas,
sem repetir os alertas locais `Alert` ou a confirmação `ConfirmDialog`
do item 2.05, e sem confundir mensagens de formulário 2.07 com notificações
globais de ações concluídas.

## Entregas

| Componente ou recurso | Implementação |
| --- | --- |
| `ToastProvider` | Provedor de notificações compartilhado por todas as rotas |
| `useToast` | API tipada para `notify`, `dismiss` e `clear` |
| `ToastNotice` | Item com título, mensagem, tom, fechar, duração e pausa |
| `OperationFeedback` | Estados `idle/loading/success/warning/error`, com retry opcional |
| `feedback.css` | Estilo responsivo com tokens da paleta aprovada |
| Integração do Hub | Provider no App, carregamento e erro de página padronizados |
| `system-feedback.test.tsx` | Testes unitários de apresentação, foco, fila, prazo e repetição |

## Matriz de estados

| Situação | Tratamento |
| --- | --- |
| Informação | Toast temporário, função `notify`, `role=status` |
| Sucesso efetivo | Toast temporário ou `OperationFeedback`, somente após confirmação real |
| Atenção | Toast persistente (`role=alert`) ou `Alert` contextual |
| Erro/falha | Toast persistente ou `OperationFeedback state=error` |
| Operação em andamento | `OperationFeedback state=loading`, sem porcentagem simulada |
| Ação irreversível | Reutilizar `ConfirmDialog` já existente; não usar toast como confirmação |
| Erro de campo | Reutilizar `FormErrorSummary` do 2.07 |

## Funcionamento

- No máximo três notificações visíveis; novas mensagens permanecem em fila
  FIFO até haver espaço.
- `info` e `success` têm prazo-padrão de 6500 ms; `warning` e
  `danger` não desaparecem automaticamente por padrão.
- `durationMs=0` mantém o aviso até dispensa; duração explícita limitada
  ao intervalo de 0 a 60000 ms.
- Temporizadores pausam por hover, foco ou mudança para aba oculta e retomam
  o tempo restante. Fechar a notificação ou desmontar o Provider cancela
  os temporizadores, sem efeitos sobre dados de usuário.
- Notificações não sequestram foco. Fechar uma mensagem nunca executa
  operação de negócio.
- O retry existe somente se houver callback `onRetry` expresso; nenhuma
  requisição, salvamento ou repetição automática.
- Conteúdo de mensagens é texto React, sem interpretar HTML arbitrário.
- Não enviar dados privados, identificadores pessoais ou segredos em toasts.
- Nenhuma chamada à rede, Firebase ou API de autenticação foi adicionada.

## Integração real

- `src/app/App.tsx` envolve o AppShell/rotas com `ToastProvider`. Nenhuma
  mensagem é gerada automaticamente quando o aplicativo é aberto.
- `src/app/LoadingState.tsx` utiliza `OperationFeedback state=loading`.
- `src/app/PageErrorBoundary.tsx` utiliza o mesmo padrão para erros reais
  de renderização, com botão de repetição e link de retorno.
- `src/app/main.tsx` importa `src/styles/feedback.css` após os demais
  estilos compartilhados; o CSS não define uma nova paleta.
- `src/components/feedback/index.ts` é o ponto único de exportações.
- Nenhuma rota ou módulo definitivo de RPG foi ativado.
