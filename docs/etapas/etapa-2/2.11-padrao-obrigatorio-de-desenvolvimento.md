Elas não são módulos implementados. O verificador aceita cada reserva

faz o módulo precisar de manifesto, entrada, teste e documento.
Pastas desconhecidas não recebem a dispensa.

A rota de `usuarios` ainda não está no catálogo oficial, por pertencer

## Regras essenciais

- Rotas passam pelo `HashRouter`, `AppShell` e `PageErrorBoundary`.
- Novos módulos ficam em `src/modules/<slug>/` com
  `module.json`, `index.tsx`, `README.md`, documento e teste próprios.
- `module.json` precisa declarar id, label, route, stage e status; rota,
  rótulo e etapa são comparados ao catálogo aprovado.
- Importações de UI devem usar os pontos públicos de `components/ui`,
  `components/data`, `components/form` e `components/feedback`.
- Módulos não recriam controles globais, folhas CSS locais nem cores
  independentes dos tokens 2.02.
- Acesso direto ao Firebase, `fetch()`, storage ou injeção arbitrária de
  HTML na camada de UI é sinalizado como violação.
- Serviços com acesso real a dados, novas rotas e publicações exigem
  autorização específica; a simples aprovação deste padrão não os ativa.

**Importante:** as verificações de regex são guardrails preventivos, e não
uma análise completa de TypeScript/JSX, privacidade ou acessibilidade.

## Testes e comandos

```bash
npm ci
npm run verify:design-system
npm run check
```

A implementação do script de verificação e seus 24 testes foi feita
diretamente na branch. O comando `verify:design-system` executa os testes
Node e inspeciona o workspace; `npm run check` também incorpora essa rotina.

**Não confirmado nesta entrega:** execução desses comandos, resultado da
CI, sucesso do TypeScript/Vitest/ESLint/Prettier, build Vite, testes de
navegador real, leitor de tela ou inspeção de segurança. Todos seguem como
pendência até existir execução registrada e analisada.

## Critérios de aceite

1. Regras e diretórios documentados, preservando a Fundação.
2. Verificador estático vinculado à rotina central de CI.
3. Testes positivos/negativos para arquivos, rotas, tokens e limites de dados.
4. Ausência de novo módulo real e ausência de publicação não autorizada.
5. Evidências claras do que foi gravado versus executado.
6. Mudanças futuras no padrão dependem de testes e aprovação expressa.
